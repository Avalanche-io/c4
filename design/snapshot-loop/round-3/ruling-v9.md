# Round 3 ruling: the streaming/projection amendment (case-v9)

Court: crucible litigation, 2026-07-13. Seven agents (advocate,
prosecutor, four evidence investigators, judge). Full record in
`ruling-v9.json` (briefs + investigations); case in `case-v9.md`.

## Opinion

All four counts are adopted with modifications. Three verified facts organize the ruling.

First, the trailing bare-ID line — the proposal's signature guarantee — is illegal under the suite's own normative text (SPECIFICATION.md:347) and rejected by every strict decoder, while libc4 silently corrupts any chain (parser.cpp:278). Those CONFIRMED fatal findings defeat Count 2 as drafted; the case file's claim that the shape is existing grammar is false at the trailing position. But the same record proves the suite already emits exactly this shape: every c4 diff file, and — decisively — every journal append (journal.go:69 writes entry line plus bare-ID boundary, so log.c4m always ends in a bare ID no strict decoder can read). C4M-STANDARD.md:648 simultaneously REQUIRES verifying such checkpoints; c4m ships contradictory pinned tests. A freeze cannot preserve a self-contradiction. Reconciliation is forced onto v1.1.0 regardless of this ruling, and only one direction avoids invalidating every existing store's journal: the trailing validator becomes normative and VERIFIED. That erratum, landed in all five implementations with one shared test vector, is the master release gate; behind it, the prosecution's fatal findings dissolve into coordinated-suite work — its own concession. The decoy-boundary objection is answered structurally: the boundary is the base-section ID, never the root, so a crash-scraped boundary fails c4 cat loudly, and the MUST-verify rule makes the final line consumer-checked. Ordered canonical emission is real engineering — the case file's 'sequential is canonical-ordered' was REFUTED — and is pinned on bytes, with buffered implementations conforming.

Second, Count 3's cost is stated, not papered over. The prosecutor's structural-invariant argument is correct: v8's '-s prints nothing but the claim' protected even negligent consumers by construction; v9 protects them by taxonomy. The court trades that narrow crash-path shield (crash timing plus ignored exit codes) for a structural fix on the success path — the founding complaint-3 consumer failed on a SUCCESSFUL run, and the guaranteed final claim line makes the naive scrape correct — and for Joshua's verbatim requirement, which the prosecution's cat -r read-back does not answer: it buffers everything before showing anything. The shield relocates rather than dies: -s -q keeps v8's empty-on-failure contract verbatim and is the blessed capture. The crash investigation's seven mandatory modifications are adopted in full, including SIGPIPE never cancelling a snapshot and streaming kill-crucible modes before freeze.

Third, Count 1's default flip survives the prosecutor's ledger-reopening charge. The license is named: Joshua's verbatim 'It doesn't have to be built in to the record as nils' — under content-default, every saved default record has nils built in. New evidence the original rejection never saw: every sibling scanner is full-native with no content mode, and full-default makes the front-door -q ID equal the journaled snapshot ID. The silent-trap objection fails safe — drift yields false-different, never false-same. The permanent 2026-07-09 projection decision is untouched. Against the advocate, -s -m c stays refused: a claim-shaped final line that is not the journaled claim rebuilds complaint 3's geometry; the cat -r composition already yields a durable content ID.

Count 4: -c stays trust-only — null-ID-implies-filter would convert a partial scan's recorded ignorance into a silent filter — and the dormant scan.WithGuide is deleted. tail -1 becomes documented, exit-conditioned contract in id(1), never a SCRIPTING recipe: pipeline substitution masks c4's exit, so -q remains THE scripted form. The help/man/changelog re-sweep, the libc4 gate, the loader unification, and the unreadable-directory exit-2 fix all gate the coordinated v1.1.0 release.

Against the ADVOCATE, the court adopts the prosecutor's position on the `-s -m c` sub-question: a final claim-shaped content-root line on a claiming invocation whose journaled claim is a different ID reconstructs founding complaint 3's geometry deliberately, and refusal is the reversible choice under a contract that freezes at v1.1.0 — the composition `c4 cat -r "$SNAP" | c4 id -q -m c -` already delivers a durable content ID at zero new mechanism, itself a consequence of eval-side projection.

C4M-STANDARD.md:648-651 simultaneously REQUIRES verifying such checkpoints (implemented by nobody), and c4m carries contradictory pinned tests (chain_test.go:86-105 vs patch_format_test.go:294-350; consumers finding 17, CONFIRMED). The prosecutor's decoy-boundary argument is met structurally, not by docs: the boundary is pinned to the base-section ID, never the root, so a crash-scraped boundary fails c4 cat loudly (crash finding 4's required resolution — and the 10.3 verification rule forces exactly this choice, since the checkpoint must equal accumulated state). The prosecutor's determinism attack is conceded as real engineering: the case file's 'sequential mode is canonical-ordered' was REFUTED (streaming finding 2 — readdir-lexical and post-order, not canonical pre-order), so ordered emission is pinned as a bytes-not-timing contract under which a fully buffered implementation conforms — the contract cannot be held hostage by the scheduler. The streaming benefits are confirmed, not hypothetical: bounded memory versus v8's full-manifest-plus-Encode-copy buffering (streaming finding 4), a killed scan leaving reusable capital, and the chain algebra resolving to the exact root ID today (streaming finding 5, CONFIRMED).

Modifications:

- Grammar reconciliation as the master release gate: one erratum to C4M-STANDARD.md/SPECIFICATION.md adopting DecodePatchChain's shape semantics (trailing bare ID at EOF = closing validator; consecutive boundaries = close-then-supersede) PLUS the 10.3 MUST-verify rule (ErrPatchIDMismatch on mismatch), landed in all five implementations (Go strict Decode, c4py, c4ts, c4m-swift, libc4) with one shared cross-implementation resolution+validator test vector, shipped by the coordinated suite release per RELEASE.md.

- Non-q id with multiple paths is refused with a teaching error (concatenated chains decode as patches on each other — contract finding 3; v8's non-q multi-path already printed only the first path); -q multi-path is unchanged.

### Count 3 — ADOPT_WITH_MODIFICATIONS

The strongest opposing argument is the prosecutor's structural-invariant argument, and it is CONFIRMED correct as far as it goes (crash finding 1): v8's '-s prints nothing until the claim' made even a negligent, exit-ignoring consumer crash-safe by construction, and Count 3 replaces that mechanism with a documented line taxonomy — a killed streaming -s leaves child IDs on stdout naming bytes possibly still at .ingest.* staging names (treestore.go:72-106), and pipeline substitution masks c4's exit status behind tail's (contract finding 4, reproduced). The court states this cost plainly and accepts it, for three reasons. First, the founding complaint-3 consumer failed on a SUCCESSFUL run (brief.md:118-122): v9 fixes the success path structurally — the guaranteed final claim line makes the naive scrape correct — where v8 fixed it only by printing nothing; the residual v9 exposure requires crash timing AND ignored exit codes, a narrow class both investigations bound (crash finding 12; contract finding 9: 'real but bounded and one-sided', legacy multi-line captures fail LOUDLY downstream). Second, Joshua's verbatim requirement — a full c4m gated to reliable capture under -s, streaming, without pipe-and-tee, without losing ergonomics (case-v9.md:53-62) — is unanswered by the prosecutor's `SNAP then c4 cat -r` two-liner, which buffers the entire snapshot before showing anything; the requirement is why the court sits. Third, the structural guarantee is not lost, it is relocated: -q keeps v8's empty-on-failure shield verbatim and `-s -q` is the blessed capture, so every disciplined consumer keeps the v8 contract unchanged. Adoption is conditioned on the crash investigation's mandatory modifications (finding 12) in full — nothing in them is severable.

Modifications:

- Claim-line definition, exit-conditioned, printed in id(1) DURABILITY, in the -s flag text itself, and in the SCRIPTING block: claims are exactly every -q line and the final bare root-ID line of an -s stream that exited 0 or 2; streamed entry lines are description, never claims; a killed stream claims nothing.

- Multi-path -s without -q is refused with a teaching error: one path per stream, or -q.
- SIGPIPE/EPIPE under -s never cancels the snapshot: the runtime disposition is handled, ingest+barrier+journal run to completion, exit 1, c4 log holds the claim (extending v7's print-failure pin from the single post-barrier line to the whole stream window); read-only id may simply exit 1.
- Every non-q -s argument form (directory, regular file, .c4m, stdin) ends stdout with its claim line — today file/.c4m/stdin -s print the ID only via the implied -q (contract finding 9).
- The unreadable-directory hard-abort (id.go:323-326 fatalf, contradicting help.go PARTIAL SCANS) is fixed to record-nulls-and-continue exit 2, so the final-line contract holds on exit 2.
- stored: <ID> is KEPT as stderr narration — v7's supersession (draft-v7.md:91) is explicitly reversed; 'parse nothing from stderr' re-affirmed.
- kill9-crucible gains streaming modes before freeze: kills at uniform offsets through scan/patch/pre-barrier windows asserting no unjournaled root ever appears as a final claim line, exit-0/2 streams recompute from the store alone, boundary IDs never resolve via cat, and SIGPIPE mid-stream still yields a journaled claim; invariant-1 comment replaced per the weakened-invariants list.

## Pinned decisions

1. Default level: c4 id lists at FULL by default and bare -q prints the full-level root ID; -m projects downward at evaluation time only.
2. Eval-side projection: the scanner captures full fidelity whenever it hashes; -m c is an output/identity-time projection with content directory IDs recomputed from projected listing text (no byte rehash); -m s/-m m remain genuinely cheaper scans whose nulls are real ignorance.
3. Null semantics: a null in any saved record means genuinely unknown at scan time; a -m c document is definitionally a projection that travels out of band (the 2026-07-09 permanent full-null decision is untouched).
4. -s -m c is REFUSED in v1.1.0, with an error teaching the composition c4 cat -r "$SNAP" | c4 id -q -m c - (which the stdin parse path must support); allowing -s -m c later is severable additive work.
5. Machine-contract cost accepted: the cross-machine content line is CID=$(c4 id -q -m c dir/), stated with 'scanned alike'.
6. Chain shape: ONE trailing refinement patch, never per-directory patches (163x decode cost measured; decoy-line multiplication).
7. Refinement content: the patch restates exactly the directory lines whose ID or size changed from their null base form; unchanged lines are never restated (restated-identical means removal); unreadable directories stay null forever; empty directories emit complete in the base section.
8. Boundary ID: the bare line opening the refinement section is the un-refined base section's own canonical-text ID, never the root ID, so a crash-scraped boundary fails c4 cat loudly.
9. Closing validator: the stream ends with the resolved root ID on a bare line, and per the grammar erratum every conforming decoder MUST verify it against the resolved manifest (ErrPatchIDMismatch on mismatch) — the final line is consumer-checked, never producer-asserted.
10. Grammar reconciliation direction: the erratum adopts DecodePatchChain's shape semantics (trailing validator; consecutive-boundary supersede) plus C4M-STANDARD 10.3 verification, in all five implementations, gated on one shared cross-implementation test vector; Decode and DecodePatchChain unify so one chain-resolving loader serves every verb.
11. -e implies buffered and emits the resolved flat manifest aligned, closed by an unpadded final root-ID line.
12. c4 id file.c4m and c4 id - emit resolved FLAT canonical text closed by the root-ID validator line — the sanctioned flattener, which also closes the founding input class (a c4m file) under tail -1.
13. Single regular-file arguments emit one entry line and NO trailing line (a listing-text validator would make tail -1 disagree with -q on the same invocation); the final-line guarantee is scoped to listing-emitting invocations: directory, .c4m, stdin.
14. Streaming is unconditional — no flag, no isatty gating; identical bytes to terminal, pipe, and file.
15. Ordered emission: canonical DFS pre-order with per-directory canonical sort at readdir, parallel hashing underneath, emission gated on next-in-order under a bounded lookahead that backpressures workers; the determinism contract is byte-identity at any concurrency and a fully buffered implementation conforms.
16. Torn tails: the emitter writes each line in one write(2), and the documented consumer rule is to discard an unterminated final line.
17. Claim semantics: claims are exactly every -q line and the final bare root-ID line of an -s stream that exited 0 or 2; streamed entry lines are description, never claims; a killed stream claims nothing.
18. Exit 2 is claim-bearing: a partial -s scan journals, prints its final claim line, and that line is true of the partial description; the unreadable-directory hard-abort is fixed to record-nulls-and-continue exit 2 before freeze.
19. Multi-path: without -q, id and id -s refuse multiple paths with a teaching error; with -q, one bare line per SUCCEEDED path in argument order survives verbatim, pairing valid only on exit 0.
20. SIGPIPE/EPIPE: under -s, stdout death never cancels the snapshot — ingest, barrier, and journal complete, exit 1, c4 log holds the claim; read-only id simply exits 1.
21. Every non-q -s argument form (directory, file, .c4m, stdin) ends stdout with its claim line.
22. stored: <ID> is kept as stderr narration, explicitly reversing v7's supersession; parse nothing from stderr.
23. Empty directory: prints exactly one line, the empty-description constant, which is consistent under both the base-reference and validator readings (the empty fixed point).
24. -c carries trust only; null-ID-implies-filter is rejected as implicit magic that would convert a partial scan's recorded ignorance into a silent filter; any future filter arrives as its own explicit flag under a named task; scan.WithGuide is deleted.
25. tail -1 is documented contract in id(1) — 'the last stdout line of a listing-emitting id invocation that exits 0 or 2 is the root ID' — always stated with its exit condition and pipeline-masking caveat, and never printed as a SCRIPTING-block recipe; -q remains THE scripted form (c4 log | tail -1 unchanged).
26. Blessed capture: SNAP=$(c4 id -s -q dir/).
27. Consumer gates: libc4 chain resolution, the five-implementation erratum with shared test vector, c4 cat's raw-echo fallback fixed, c4 paths' first-line dispatch fixed, and the CLI loader unification all gate the coordinated v1.1.0 suite release.
28. Crucible gate: kill9-crucible gains streaming -s kill windows and a SIGPIPE mode with the replacement invariant and passes before freeze.
29. Docs gate: the full help/man/changelog re-sweep ships with v1.1.0, including one-line migration notes for the -s stdout shape change and the default-level change.
