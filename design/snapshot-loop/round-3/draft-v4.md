## Round-3 freeze-check fold — five blockers, five total rules

1. **Hard links → not recorded; the fidelity boundary corrected (amends the decided boundary item under the concrete-defect standard).** Defect: v3 asserted recording ("records … hard links within the tree"; "recreated as groups") but defined no listing encoding, no knowledge-level assignment, and no verification rule — two conforming implementations mint different snapshot IDs for the same tree, or linkness leaks into content form and falsifies "equal iff byte-identical" (`ln a b` vs `cp -p a b`). No compliant encoding exists: the grammar is frozen (no field for it), and a link-group entry naming a path in another directory's subtree makes listing bytes depend on paths outside the entry's own subtree — the exact root-relativity defect that REJECTED conditional symlink IDs (unstable subtree IDs; byte-perfect subtree restores failing verification). Total rule: **no listing form records link structure; a hard-linked file scans as an ordinary file** (its bytes; observed mode/mtime in full form), so linkness never affects an ID at either level; restore materializes every file entry as an independent file — a hard-linked tree restores with identical bytes and independent inodes, wherever the partners lived; link structure joins ownership/xattrs/ACLs on the not-recorded side of the boundary (sidecar territory). This withdraws an unimplementable claim rather than narrowing a working one: nothing shipped or specified ever encoded it.

2. **Folded sequences → recomputation is target-guided.** Defect: v3 never said whether verification's recompute re-folds; folded targets are constructible (`id -s -S` is legal — only `-m` conflicts with `-s` — and a saved `-S` description can be snapshotted and restored), so a byte-perfect restore exits 0 in one conforming implementation and 3 in another, the exit-3 one printing a false claim on a perfect tree. Total rule: **folding is a scan choice recorded in the listing, never a verification choice** — wherever the target records a folded entry, the recompute folds exactly the member files that entry records (their recomputed IDs form the ID list, hashed as the entry's ID) and nothing else, however foldable the tree looks; the dry-run plan computes the same way; diff against a description folds what that side records; the pre-image is a complete default scan (nothing excluded, nothing folded). Byte-perfect restores of folded targets verify exit 0; `-S` at snapshot time never changes what verification demands.

3. **Unreadable directories → the partial-scan rule is total for every entry kind.** Defect: the scan rule pinned files only, so `chmod 000` on a subdirectory let conforming scanners diverge — null-ID directory entry vs omission, plus an uncomputable size field — the same divergence class the sizes-derive-from-scan pin was adopted to kill. Total rule: **an unreadable entry records exactly what the scan observed** — name and kind from the parent's listing; observed mode/mtime in full form; null for everything unread, always size and ID (sizes and IDs derive from reading, and nothing was read); an unreadable directory is a directory entry with null size and null ID recording no children; sockets/fifos/devices stay omitted. Directory size restated so the sum is always computable: **the total file bytes the scan read beneath it** — recursive, the rule the transcript's sums already demonstrated (this also closes the check's non-blocking direct-vs-recursive wording note); unread entries contribute nothing. Same tree, same access outcomes ⇒ same listing bytes from every conforming scanner.

4. **Null-ID target entries → keep-as-found, and exit 2 owns every omission.** Defect: at a null-ID file entry a conforming restore could keep or destroy a pre-existing file (both exited 2 — the destructive verb's resulting tree was implementation-defined); a null-ID directory entry had no materialization rule at all, and conflict 7's FILE-only precedence pin routed it to exit 3, whose "re-run to finish" advice can never terminate for a permanent target-side condition. Total rule: **restore never creates, modifies, or removes anything at a null-ID entry's name** — whatever `<dir>` holds there is left exactly as found, absent stays absent (maximally non-destructive; the target itself lacks the knowledge); each omission listed on stderr; **exit 2 iff every difference between the as-built tree and the target sits at a null-ID target entry — file or directory** (symlink entries carry no ID by rule and are never omissions). Conflict 7's pin widens from FILE to any null-ID entry; exit 3 is again reserved for conditions a re-run can actually fix. Line 2 stays a true recomputable claim: kept content hashes as itself; kept nothing is simply absent.

5. **`c4 log` byte-stability → scoped per journal file (amends the decided log-layout item).** Defect: the unconditional sentence "a line, once printed, is printed identically by every future run" is falsified by the design's own sanctioned split recipe, which renumbers surviving sections — two decided items in direct contradiction. One scoping clause: **byte-stability holds over any given journal file; the index is a per-file coordinate, never a permanent name; the entry text after the index is immutable history in every file that carries it**; split installs a new file whose sections count from 1, stated at the recipe in gc(1).

## Conflicts adjudicated (round-2 prosecution; each with the defect that decided it)

1. **`c4 log` layout → index + verbatim canonical entry (freeze-auditor); padded columns REJECTED.** Concrete defect in the padded form: widths are computed per invocation across all lines, so one later long name re-renders every earlier line — a layout called frozen that is not byte-stable (and "minimum two spaces" licenses byte-divergent conforming outputs). Adopted layout: one line per entry — the section's 1-based index, one space, the entry line exactly as recorded. Adds nothing (the entry is already canonical c4m); every printed line is immutable for the life of the journal file it indexes (round-3 amendment, repair 5: byte-stability is scoped per journal file — the index is a per-file coordinate, split installs a new file whose sections count from 1, and the entry text after the index is immutable in every file that carries it); first field = index (the exact `c4 split` coordinate), last field = ID (fields never contain unescaped spaces). The same rendering applies to explicit chain arguments (sections with several entries repeat their index), eliminating the "generic behavior out of scope" contradiction with the another-store's-journal example. The journal FILE is the contract; log output is a view of it.

2. **gc concurrency → shared/exclusive sweep lock (freeze-auditor), completed; re-verify/re-put protocol REJECTED.** The reopened defect (concrete, no crash needed): a `gc --force` sweep between an ingest's staging and its journal append deletes staged-but-unrooted objects; the ingest's dedup checks already passed, so it appends and prints an ID whose closure is gone — "printed ⇒ durable" and "journal line ⇒ durable" both falsified. The edge-pinner repair (gc holds the append lock through delete; ingests re-verify and re-put post-lock) fails at three points its own case exposed: the mark set could be computed outside the lock and go stale (a conforming gc deletes a just-journaled snapshot); a stdin blob cannot re-read stdin to re-put; re-put objects need a second flush barrier only inference supplied. Waiting is simpler than repairing. Merged contract, two named locks: the decided **append lock** unchanged (truncate-repair + append + fsync, serializing appends among all writers); a **sweep lock** — ingests (`id -s`, `| c4 -s`) and `restore --force` hold it shared for their whole duration (staging through claim; for restore, through verification), `gc --force` holds it exclusive from BEFORE it reads the journal (mark) until the sweep finishes, dry run lockless. Consequences: the mark set cannot go stale; nothing an in-flight ingest staged can be swept; restore's content pulls cannot race a sweep (mooting the unjournaled-target race); no repair protocol exists to get wrong. Lock order is sweep-shared then append; gc takes only the sweep lock — no deadlock. Locks are per store and live in the write store; closures resolved from secondary read stores are as stable as those stores' own discipline (a failed pull mid-restore is loud — rehash-verified — and exits 3 with line 1's undo standing).

3. **Symlink identity → always-null IDs (stronger than either revision); conditional in-tree IDs REJECTED.** The spec's derivation rule (symlink ID from target content; directory target = target's manifest ID) was reopened with a concrete identity defect: `ln -s . self` makes a directory's listing contain its own ID — a self-referential Merkle cycle, literally uncomputable — and out-of-tree targets leak bytes outside the tree into a content ID, breaking T3's pure-function-of-the-checkout property and forcing restore verification to read outside `<dir>`. The freeze-auditor's conditional repair (real ID iff the target resolves lexically to an in-tree regular file) has its own concrete defect: it is root-relative — the same subtree yields different listing bytes under different scan roots, so the surface's own subtree-restore example fails verification on a byte-perfect restore, subtree dedup breaks, and `diff SNAP/src liveSrc/` is permanently non-empty. Merged rule, unconditional: **a symlink entry is its name, its target text, and a size equal to the target text's byte length; mode, time, and ID are null in every listing form; a symlink names no store object.** Every consequence is load-bearing: identity is a pure function of the tree at every root (subtree IDs are stable, dedup and diff work); cycles are unconstructible (no listing ID ever derives through a link); verification never reads outside `<dir>`; the entry is complete without an ID, so symlinks are never exit-2 omissions and always materialize; mid-path refusal in ID/path is forced by construction rather than chosen. `cat` of a symlink component errors, printing the recorded target. Grammar untouched — nulls are first-class, the identical doctrine as the decided null-stat listing pin. Legacy target-derived symlink IDs are covered by the existing migration note (valid full-form text objects; re-derive with one recompute).

4. **Store-address dispatch → global classification, per-verb acceptance.** Both revisions leaked the ID-dispatch paragraph into c4-id(1) while §2 pinned acceptance at exactly three places, leaving `c4 id <ID>` defined twice (or not at all). Merged: the syntactic classification is global — an argument whose first slash-separated component is **90 characters, begins `c4`, and is entirely base58** (the full three-part predicate, stated identically everywhere) is a store address in every verb and is never silently hashed as a local file; `./` forces the filesystem; the ID test precedes the `.c4m` suffix test, and a store path's final component named `*.c4m` yields bytes (files are always bytes). Acceptance stays exactly `cat`, `restore` targets, `diff` sides; `id` and every other verb refuse a store address with a teaching error that prints the composition (`c4 cat -r <ID> | c4 id -q -`) — the patch-teaches-restore idiom. Dispatch is again a total pure function of argument text, with its per-verb domain stated.

5. **Remote stores → definitional scoping; per-verb refusal matrix REJECTED.** One sentence — "a store is a directory on a local filesystem; this contract defines no semantics for network or object stores" — instead of four refusal rules for a thing the config cannot express. Reads consult configured stores in order; writes and the journal go to the first. Networking remains a declared non-goal; any future remote store must re-prove the print barrier and journal equivalence for its medium.

6. **Narration → light non-contractual pin; frozen summary grammars REJECTED.** Detection is isatty(stderr) and nothing else (no env sniffing, no TERM, no CI detection; nothing is colored). On a terminal: one live line rewritten in place with CR, no escape codes, replaced at completion by one summary line; otherwise exactly one summary line. Declared non-contractual: parse nothing from stderr; every load-bearing datum is on stdout or in the journal. Freezing exact summary grammars invites the parsing the declaration forbids, and the frozen shapes already self-contradicted (an em dash one bullet after a "plain ASCII" pin). Transcript shapes are illustrative, not contractual.

7. **restore contract → plan at target level, as-built line 2, exit 3 (freeze-auditor), completed with its prosecutor's two pins.** Reopened defects: (a) for a content-ID target, the decided sentences "boundary IDs equal when matching" and "plan line 1 is exactly what --force prints" (a full-form pre-image) cannot both hold; (b) under exit-2 omissions a "verified target ID" line 2 is unprintable, and "both lines equal when matching" was false for content targets; (c) without exit 3, exit 1's "nothing modified" is falsified by any post-line-1 failure. Merged contract: the plan is computed at the target's knowledge level (line 1 = `<dir>`'s current ID at that level; matching ⇔ no entry lines ⇔ equal boundaries; plan-line-1 = force-line-1 holds exactly for snapshot-ID targets). `--force` prints **at most two lines and nothing else**: line 1 = the full-form pre-image snapshot ID, always before the first modification; line 2 = the verified, recomputed ID of `<dir>` as restore left it, printed whenever recomputation completed (always on exit 0 and 2). **Exit 0 ⇔ line 2 equals the target ID.** Precedence pin (round-3 amendment, repair 4, widens FILE to any null-ID entry): **exit 2 iff every difference between the recomputed as-built tree and the target sits at a null-ID target entry — file or directory, kept as found, never touched** (symlink entries carry no ID by rule and are never omissions); any other post-line-1 divergence — OS-refused operation, concurrent mutation, failed store read — is **exit 3**, with line 1 printed, its undo standing, and line 2 present iff recomputation completed. Every printed line is a true, recomputable claim in every outcome; line count plus exit code fully determines state.

## Verdict shape

1. **The print barrier.** A snapshot ID reaches stdout only after everything the ingest stored — file bytes, listings, the journal entry — is on stable media. Printed means durable; unprinted means nothing was claimed: the source tree was never written to, the store's prior contents are intact, rerun is idempotent. Readable from the store side: any complete journal line found after a crash names a fully durable snapshot, verifiable in one pipe (`c4 cat -r ID | c4 id -q -`); a torn tail belongs only to an ingest that never printed. v2.5 made the equivalence unconditional against concurrent `gc --force` (sweep lock); v3 states it interruption-agnostic — the equivalence is ordering-derived, so a killed process, a kernel panic, and power loss are one case.
2. **The journal.** The store names its own roots: every `-s` ingest (snapshots, stdin blobs, single files) and every `restore --force` pre-image (including empty ones) appends one section to `<store>/log.c4m`, an ordinary c4m patch chain; `c4 log` lists it byte-stably (per journal file — repair 5), oldest first; nothing journaled is collectable until the journal is explicitly split. There is deliberately no ref namespace: handles are IDs; the journal is the reflog.

## 1. Identity — one mechanism, two named knowledge levels

One naming rule (frozen): the C4 ID of canonical bytes; for a directory, the one-level canonical listing of its direct children. Two named levels:
- **content ID** — listing with mode and timestamp null; names, sizes, symlink targets, and child content IDs real. Equal iff contents are byte-identical, on any machine, clock, or umask. Default level for `c4 id`; answers T3 by string equality.
- **snapshot ID** — listing with everything observed; directory entries carry child full-listing IDs; every ID in any listing is the hash of the exact text of the object it names. Printed by `c4 id -s`; the recovery handle.

Pins: sizes derive from the scan itself — a file's recorded size is the byte count actually hashed (never a separate stat, closing the stat-vs-read divergence that could mint permanently unverifiable snapshots), a directory's size is the total file bytes the scan read beneath it (recursive; entries recorded with null ID contribute nothing — repair 3), a symlink's size is its target text's byte length. Symlink entries per conflict 3 (name + target text; mode/time/ID null everywhere). Hard links per repair 1: no listing form records link structure — a hard-linked file is an ordinary file entry, so linkness never affects an ID at either level. The root's own mode and mtime appear in no listing (verified against shipped WriteCanonical): provenance, not identity — not stored, not restored, not verified. Empty fixed point: an empty directory's listing is empty text, so its content ID and snapshot ID equal the empty-description constant, the same ID as zero bytes (verified against id_test.go). A single file's snapshot ID and content ID coincide (its bytes). Flatten rule unchanged: a description's canonical-text ID equals its root ID at its own knowledge level — the pipe law and snapshot-ID recomputability are one rule. `-q` is output form, never identity selection (level chosen by `-m`, default content). Hash axiom stated once: ID equality is SHA-512 equality; every store read is rehashed against the requested ID (ledger-accepted). Dispatch: `.c4m` and `-` parse as descriptions (unparseable `.c4m` errors); all other file arguments are bytes; files inside scanned trees are always bytes; chains resolve to final state (`patch -n` for earlier); store-address classification per conflict 4. Listings scale with direct-child count; both graphs dedup across snapshots (O(changes) history with no history feature).

## 2. Self-description — the store alone recovers everything, and is addressable

`c4 id -s DIR` is a total ingest: file bytes; per-directory full-form and content-form listings (root included); one journal section per path argument. `-s` writes only inside the store: no `.c4m` file, nothing in the scanned tree or working directory, ever. Multi-path `-s`: paths snapshot in argument order, each claimed independently (one stdout ID line and one journal section per path, printed only after that path's own claim point); all paths are attempted; exit = 1 if any failed, else 2 if any scan was partial, else 0. `id -s file` stores the file's bytes and journals them. Ingesting a description stores its listings only; `restore` pre-flights the closure. A snapshot is one walk: a tree mutated mid-scan yields a valid snapshot of what the walk read — internally consistent (every field derives from the hashed read), not atomic point-in-time. Partial knowledge is total-ruled (repair 3): an unreadable entry records name and kind from its parent's listing plus every field the scan observed, with null for everything unread — size and ID always; an unreadable directory is a directory entry with null size and null ID recording no children; sockets, fifos, and devices are omitted; the same tree under the same access outcomes yields the same listing bytes from every conforming scanner.

**The store has no object types — cat is bytes.** Forms that must interpret an object (`/path` descent, trailing slash, `-r`, every restore target) parse the fetched bytes as a listing and error if they do not parse; below a root, kinds come from the listing itself (a trailing-slash name is a directory entry), so descent is gated by the recorded entry kind, never by whether fetched bytes happen to parse — the root is the one parse-gated step because it has no containing entry. No sniffing anywhere.

**ID/path edge semantics (round-1 open 1, closed).** Where accepted (cat, restore targets, diff sides — exactly three): components split on `/`; empty, `.`, `..` are errors; matching is byte-exact against decoded recorded names (directory entries match with or without their trailing slash; no globbing, case folding, or normalization); a folded sequence matches only its folded name — a member filename errors naming the folded entry; a hand-crafted listing holding both `x` and `x/` refuses bare `x` as ambiguous (`x/` names the directory; the file is reached by its entry's ID). Every non-final component must match a directory entry (file mid-path: "not a directory"; symlink mid-path: error printing the recorded target — paths never follow symlinks, and under always-null IDs there is nothing to follow). Final component: directory → its listing; file → its bytes; folded sequence → the object its recorded ID names (its ID list; members fetched by those IDs); symlink → error printing the recorded target; null-ID entry → error. Trailing slash asserts the result is a listing (`ID/` asserts the root parses as a listing; as a restore target `ID/` ≡ `ID`). Every fetched level rehash-verified. `.c4m` files and `-` are whole descriptions and never take `/path`. The sugar is exactly the documented walk (cat the listing → read the entry's ID → cat that ID) — never more, never less. Resolution failures are uniform: every kind exits 1 with human-level stderr text; a machine distinguishing cases walks the listings instead of matching stderr (ledgered accepted tradeoff, round-3).

**Journal entry, one total rule per field (round-1 open 2, closed).** `- <UTC time> <size> <name>[ <- <host>:<abs-path>] <ID>` + chain boundary; one section per ingest. mode always null. time = UTC wall clock at append, RFC 3339 seconds (provenance, never identity). size = byte size of the object the entry's ID names (a snapshot's root listing text; a blob's bytes; 0 for the empty description). name = final component of the argument's absolute path (`filepath.Abs`, lexical; symlinks not resolved), with `.c4m` appended iff the ingest produced a description AND the name does not already end in `.c4m` (so `id -s saved.c4m` journals `saved.c4m`, `id -s notes.txt` journals `notes.txt`); the filesystem root journals `root.c4m`; stdin journals the constants `stdin` (raw blob) / `stdin.c4m` (parsed description). Names recorded in grammar name-encoding; names are history, never resolved (catalog resolution stays rejected). origin = `<host>:<absolute path>`, parsers splitting at the first colon (Windows drive colons belong to the path); host = the hostname's first dot-delimited label with characters outside [a-zA-Z0-9_-] replaced by `-`, prefixed `h` when it would not begin with a letter, `localhost` when empty — a total transform closing the latent flow-target charset break. Stdin ingests record no origin link (the grammar's optional link; no pseudo-path). ID = the journaled object's ID, always the last field.

**Journal growth**: one short line per ingest, not data (~10^6 ingests ≈ half a GB of text); appends inspect only the file tail (torn-tail repair scans back one maximal section); `log` streams; `gc` reads it once per run. Shortening is the explicit split recipe.

## 3. Durability — printed means durable; journaled means durable; measured, not aspirational

Protocol unchanged: temp + fsync + atomic rename per object (presence under a final name implies verified-at-write integrity, keeping dedup's Has() valid after a crash); barrier; journal append + fsync (under the append lock, torn tail truncated first); barrier; print; exit 0. Platform honesty: the contract is the ordering — synced before renamed, barriered before journaled, journaled before printed — enforced with the strongest primitives each platform offers (macOS fsync + F_FULLFSYNC barrier; Linux fsync of files and containing directories + device flush; Windows FlushFileBuffers + atomic replace); the promise is exactly as strong as those primitives; constants are measurements from one machine (Apple-silicon APFS SSD: ~130 µs/file + two ~5 ms barriers beyond reading and hashing, which dominate; 20,312 files / 4.8 GB ⇒ ~3.5 s read+hash + ~2.6 s durability ≈ 6.1 s). Per-file F_FULLFSYNC and `--no-fsync` stay rejected. Journal-line equivalence and torn-tail repair carried from v2, unconditional under the sweep lock (conflict 2), and — v3, sim fold — **interruption-agnostic**: every claim in this section is a consequence of the write ordering alone, so a killed process, a kernel panic, and power loss are one case; at every instant, anything claimed (journaled or printed) is already durable, and anything unclaimed leaves at most a torn journal tail the next writer truncates. "Advisory" locking scopes to c4's own writers, which are the only sanctioned writers of files inside a store; a foreign process editing store files is corruption, and corruption is loud, never silent — every read is rehash-verified and every journal line is a claim recomputable in one pipe. Materialization keeps the strong promise (temp+fsync+rename per restored file; verify by recomputation at the target's knowledge level; barrier; then line 2); between restore's lines the tree holds a mix of old and new whole files, both endpoints durable in the store.

## 4. Destructive reconcile — one tree-writer, plan by default, pre-image before destruction

`restore` is the only verb that writes working trees; `patch` stays pure text algebra and errors on directories with the teaching message. Carried: dry-run default; `--force` = pre-flight closure (missing ⇒ list, exit 1, touch nothing) → full-fidelity pre-image, durable and journaled before the first destructive operation, printed as line 1 → reconcile → verify → line 2; completeness gate (unreadable files or directories, sockets, fifos, devices — symlinks, broken or not, are fully recordable: a link is its name and target); no pre-image opt-out; targets are descriptions only (ID[/path] landing on a directory entry — a file or symlink final component refused with "extract files with c4 cat"; `.c4m`; `-`); mirroring via `$(c4 id -s A)`; `--source` rejected (headroom preserved); empty-description constant as pre-image of absent/empty dirs; concurrent restores uncoordinated (accepted tradeoff). Verification per knowledge level carried, total: snapshot targets apply recorded modes/mtimes then recompute full-form; content targets recompute content-form (platform-default metadata defined, unclaimed, unverified); symlinks recompute as name + target text + target length with nulls, so verification is a pure function of `<dir>`. Recomputation is target-guided for sequences (repair 2): it folds exactly the member files the target's folded entries record and nothing else — folding is a scan choice recorded in the listing, never a verification choice — so byte-perfect restores of folded targets verify exit 0; the dry-run plan computes the same way; the pre-image is a complete default scan (nothing excluded, nothing folded).
