## Verdict shape

1. **The print barrier.** A snapshot ID reaches stdout only after everything the ingest stored — file bytes, listings, ID-list objects, the journal entry — is on stable media, under each platform's honest primitives. Printed means durable; unprinted means nothing was claimed. Readable from the store side: any complete journal line found after any interruption (kill -9, panic, power loss — one case, by ordering) names a fully durable snapshot, checkable in one pipe (`c4 cat -r ID | c4 id -q -`); a torn tail belongs only to an ingest that never printed. Unconditional the simple way: no collector exists to race.
2. **The journal.** The store names its own roots: every `-s` ingest and every `restore --force` pre-image appends one section to `<store>/log.c4m`, an ordinary c4m patch chain; `c4 log` lists it byte-stably per journal file, oldest first; an absent journal is an empty history. Nothing it references is deletable by any c4 verb; the installed journal is the complete root set a future collection design consumes. No ref namespace: handles are IDs; the journal is the reflog.
3. **stdout is the API.** Every verb's stdout is enumerated and byte-pure; extraction is whole-line capture, fields, or line N — never regex over prose; stderr is narration under the light non-contractual pin; exit codes are contract; `explain` is the one prose verb, so no other verb has to explain itself.

## 1. Identity — one mechanism, two named knowledge levels

One naming rule (frozen): the C4 ID of canonical bytes; for a directory, the one-level canonical listing of its direct children (Merkle). Two named levels, the only two user-visible identity concepts:
- **content ID** — the listing with mode and timestamp nulled entirely (the permanent 2026-07-09 full-null decision: no exec bit; the ID does not self-describe its projection; comparisons are like-mode; the projection travels out of band). Names, sizes, symlink targets, child content IDs real. Scanned alike — same -S choice AND same exclusion choices (the -m term is dropped: a content ID is definitionally the content projection) — equal exactly when contents are byte-identical, on any machine, clock, or umask. Default level for `c4 id`; answers T3 by string equality.
- **snapshot ID** — the listing with everything observed; directory entries carry child full-listing IDs; every ID in any listing is the hash of the exact text of the object it names. Printed by `c4 id -s`; the recovery handle.

All v6 pins carried verbatim: sizes derive from the scan (file = bytes read and hashed; directory = total file bytes read beneath, null-ID entries contributing nothing; symlink = target-text length); symlink entries are name + target text with mode/time/ID null in every form, naming no store object, null target text when readlink was refused; hard links are never recorded in any listing form; folded sequences fold only under -S and record the folded name plus an ID naming the ID-list object (member file IDs, one per line, in the folded range's order — line N names the range's Nth member), size = sum of member sizes read and hashed, full-form mode = shared member mode, mtime = newest member mtime, and a run folds only when every member is a plain file, every member's bytes were read and hashed (never a null-ID member), and every observed mode is equal — an unreadable member unfolds the run, identically in every implementation; a directory's own mode and mtime appear only in its parent's full-form entry, never in its own listing, and the parentless scan root's mode, mtime, and kind appear nowhere (provenance, not identity); argument roots resolve with ordinary OS path resolution in every verb, final component included, dangling links erroring, symlink-ness recorded only for entries; empty fixed point (empty directory ≡ zero bytes ≡ the empty-description constant); a single file's two IDs coincide; the flatten rule (a description's canonical-text ID equals its root ID at its own knowledge level — which is why `c4 id -q file.c4m` prints THE identity of a c4m file, at the description's own level); `-q` is output form, never identity; ID equality is SHA-512 equality with every store read rehashed; dispatch (`.c4m`/`-` parse; all other files are bytes; files inside scanned trees are always bytes; ## 2. Self-description — the store alone recovers everything

`c4 id -s DIR` is a total ingest: file bytes; per-directory full-form and content-form listings (root included); the ID-list object of every folded entry; one journal section per path argument. `-s` writes only inside the store — no .c4m file, nothing in the scanned tree or working directory, so T1's "delete everything outside the store" destroys the empty set by construction. Multi-path `-s`: argument order, claimed independently, all attempted; exit 1 if any failed, else 2 if any partial, else 0; stdout carries one ID line per path that succeeded (§5). `id -s file` stores and journals the file's bytes. Ingesting a description stores its listings only; restore pre-flights the closure. Partial knowledge stays total-ruled exactly as v6: unreadable entries record name, kind, and observed fields with null size and ID; unreadable directories record no children; unreadable symlink targets record null target text; an unreadable member unfolds its run; a scan attempts every name its parent enumerates in canonical order; sockets, fifos, devices, and kind-unobservable entries are reported and omitted; the same tree under the same access outcomes yields the same listing bytes from every conforming scanner. The store has no object types — cat is bytes; what an ID names is knowledge the caller brings; no sniffing anywhere. ID/path edge semantics carried whole (byte-exact matching, no store-side name folding, folded entries matched only by folded name, x-vs-x/ ambiguity refused, symlinks never followed in recorded paths, every level rehash-verified, trailing slash asserts a listing, uniform exit-1 resolution failures with machines walking the listings).

## 3. Durability — printed means durable, on each platform's honest terms

**The claim sequence (amended under the concrete-defect standard — renames deferred past the data barrier):** (1) every object is written to a temporary name and flushed per-file; (2) a barrier makes ALL staged bytes stable; (3) objects are atomically renamed into place — so no object ever appears at its hash name before its bytes are on stable media; (4) the journal entry is appended and flushed (under the append lock, torn tail truncated first); (5) a second barrier; (6) the ID prints; exit 0. The defect this closes: under the old per-object stage-sync-rename order, a power cut could leave a torn object at its final name (rename metadata committed, data lost from the drive cache), which a re-run would adopt by presence and claim in a printed snapshot — falsifying printed⇒durable and routing an uncurable condition to exit 3. Barrier count and measured constants are unchanged.

**The ordering is the contract on every platform; enforcement and cost are platform-honest:**
- **macOS/Linux**: per-file fsync ≈126 µs measured; one device-cache barrier (~5 ms) before the renames and a second before the print; Linux adds containing-directory fsyncs so renames are stable no later than the journal entry. Measured whole (APFS, M-series, the brief's frozen physics): 20,312 files / 105 MB ingests with store in ~4.3 s; materialize ~4.4 s; no-op re-apply ~0.3 s. Per-file F_FULLFSYNC stays rejected here — the batch barrier exists and is three orders cheaper.
- **Windows**: no batch barrier exists for an unprivileged process (a directory handle cannot be flushed; volume flush needs administrator rights), so the per-file flush IS the durability: each object's bytes are flushed through to media before its rename; each rename is issued with write-through semantics so the rename is stable no later than the journal entry; the journal append is flushed before the print. Same ordering, same printed-means-durable and journaled-means-durable sentences; a different cost shape — durability cost scales with objects stored, and a first 20k-file snapshot plausibly takes minutes (derived from per-file write-through at milliseconds each; stated because T4 asks, labeled derived because no Windows constant has been measured). The write-through-rename mechanism claim is itself flagged as documentation-derived, unexercised — a scheduled verification obligation, not a settled fact.
- **Every OS**: the promise is exactly as strong as the platform's flush primitives; a drive that acknowledges a flush it has not performed can lose what was printed.

**Consequences, interruption-agnostic (kill -9, kernel panic, power loss are one case, because everything derives from ordering):** printed ⇒ fully durable, even one microsecond after printing — a printed ID never dangles: if it printed, you can get it back; any complete journal line after a crash names a fully durable snapshot even if its command never lived to print, recomputable in one pipe; unprinted ⇒ nothing claimed — the tree untouched, store and journal intact, stray staged objects and partially-surviving renamed objects all carry good bytes (the barrier preceded every rename) and a re-run adopts or ignores them safely.

**What repeats never re-pays (T4), honestly:** a repeat snapshot re-reads and re-hashes every byte — mtimes are never trusted; trusting them would be assertion — and skips only the store WRITES of objects already present, the skips counted on the one stderr summary line. The skip is safe two ways: presence at a hash name now implies bytes on stable media (barrier-before-rename), and every consumer read rehashes, so a wrong object at a right name (foreign edit, bit rot) is loud at first read. Presence gates writes; reads verify bytes; presence never answers an integrity question — the membership probe reads (§5). Derived, labeled derived: the touch-3-files re-snapshot pays full read+hash but almost none of the per-file durability work that dominates the measured 4.3 s — well under half the first run; on Windows, where durability is the whole cost, the saving is larger still. Materialization keeps the strong promise: stage + flush + rename per restored file under the same ordering; interleaved-observation verification; then line 2. Between restore's lines the tree holds a mix of old and new whole files — never torn files — with both end states durable in the store.

## 4. Destructive reconcile — one tree-writer, plan by default, pre-image before destruction, undo to any depth

`restore` is the only verb that writes working trees; `patch` stays pure text algebra with the teaching error. Carried whole from v6 with all repairs standing: dry-run default (plan in c4m patch form at the target's knowledge level, folded as the target folds; line 1 = <dir>'s current ID at that level; matching ⇔ no entry lines ⇔ equal boundaries; plan-line-1 = force-line-1 exactly for snapshot-ID targets recording no folded entries). `--force` pipeline: (1) pre-flight closure — every ID the target names must resolve, else listed, exit 1, nothing touched; (2) completeness gate — unreadable files/dirs/symlink targets, sockets, fifos, devices refuse exit 1 untouched (a readable symlink target, broken or not, is recordable); (3) the pre-image — a complete default scan, nothing excluded, nothing folded — durable AND journaled before the first destructive operation, printed as stdout line 1; (4) reconcile (per directory: unrecorded entries removed first, then recorded entries materialized in listing order, every name claimed create-exclusively; materialization never replaces an entry it did not itself reconcile), interleaved-observation verification, line 2. Targets are descriptions only; mirroring is `restore --force $(c4 id -s good/) bad/`; `--source` stays rejected; no pre-image opt-out; the empty-description constant is the pre-image of absent/empty dirs; `<dir>` resolves with OS path resolution, final symlink followed, dangling-link-occupied names refusing exit 1, absent dirs created with missing parents and platform-default metadata; concurrent restores uncoordinated (accepted tradeoff).

Verification: every field of line 2 observed from the filesystem in this run, each at the last moment it remains observable — written files read back and rehashed after sync before their recorded mode lands; kept files hashed by this run's pre-image; modes and mtimes children-before-parents, so recorded modes that deny the restorer read still verify exit 0 (the residue honestly stated: a later re-scan there needs read granted first, honest history in the next pre-image). Recomputation is target-guided for sequences; folded members materialize with the entry's one recorded mode and mtime. Content-ID targets verify names, sizes, symlink targets, bytes; modes/times are unclaimed platform defaults — exec bits are not preserved there (full-null), stated where it bites: snapshot IDs are the recovery handle, content IDs the comparison handle. Exit machine carried as amended round-5, plus the print-failure pin: 0 ⇔ line 2 equals the target ID; 1 refused-before-modification; 2 declared omissions only (incomplete entries kept as found; destination fold-collisions first-claimant-kept; names the destination cannot spell — invalid encoding, forbidden characters, reserved names, length — nothing materialized), line 2 printed and true, re-run cannot close; 3 curable only — permission, space, transient I/O, concurrent mutation, failed store read, failed stdout write — cure-then-re-run, line 1's undo standing, no permanent condition ever routed here. Restoring a snapshot taken with exclusions REMOVES the excluded names from the live tree like any unrecorded entry — warned at both surface sites; the pre-image holds them.

**Undo, and the retention behind it (T2):** line 1 reverses the operation byte-exact, recorded metadata included; the undo prints its own line 1, undoable to any depth; handles are IDs in three places — stdout line 1 (scripts; a bare ID, itself a valid target), the stderr hint as a complete command (humans), the journal (permanent; `c4 log` is the reflog; a lost terminal loses nothing). **Nothing expires:** no c4 verb deletes store objects; every pre-image is a journaled snapshot; every handle keeps working for as long as the store directory exists. The future collection verb — out of scope — inherits: the installed journal as its complete root set; the pin that nothing a journal line reaches is ever collectable; the closure rules (both listing graphs; a folded entry's closure includes its ID-list object and every member); and conflict-2's shared/exclusive sweep-lock protocol, which it must use to re-prove the print-barrier equivalences unconditional before it may delete anything.

## 5. The machine-output contract (founding complaint 3 — frozen product surface)

stdout is data, byte-pure; stderr is narration under the light non-contractual pin (isatty live line replaced by ONE summary line; parse nothing). The identity a consumer needs is always a whole line on stdout — never a token inside prose or entry text, never on stderr. The shipped `stored: <id>` stderr line is superseded.

Per-verb stdout, total enumeration:
- **id**: c4m description text. With **-q or -s: one bare-ID line per path that SUCCEEDED, in argument order, nothing else on stdout** — a failed path prints no line, so positional attribution is valid only on exit 0; the sanctioned script form is one path per invocation (`SNAP=$(c4 id -s dir/)` is single-path by construction), and the first-screen rule carries its rationale so the restriction reads as physics, not folklore. A stdout write failure never rolls back store work: exit 1, the claim journaled, `c4 log` holds the ID, a re-run reprints it.
- **cat**: the object's bytes exactly, or nothing (bytes must rehash to the requested ID or cat writes nothing, exit 1; absent vs corrupt on stderr only). The membership probe is `c4 cat "$ID" >/dev/null` — exit 0 = present AND byte-verified; it reads the whole object, and that cost is stated, because a stat-only yes would be assertion. A nonzero probe is deliberately ONE answer to a consumer — no verified bytes, absent or damaged alike; the why is stderr narration for humans (explicit accepted tradeoff; per-kind exit codes are a rejected class; healing is future fsck territory).
- **restore**: dry run — the plan (c4m patch text). --force — at most two lines, EACH A BARE ID: pre-image ID, verified as-built ID; line 1 is itself a valid restore target (the undo, shown as a first-screen recipe); line count plus exit code fully determines state; capture stdout whole then split (early pipe close can interrupt a verb mid-print; a lost line is never lost state — line 1 is journaled and the as-built ID is recomputable); a failed stdout write exits 3 and a re-run reprints.
- **log**: one line per section — 1-based per-file index, space, entry verbatim; fields never contain unescaped spaces; first field the index, last field the ID (`c4 log | awk '{print $NF}'` is field extraction of structured records, scoped honestly to the installed journal).
- **diff/patch/merge/intersect**: c4m text. **paths**: path lines. **explain**: prose — the one prose verb; scripts have no business parsing it.
The recipes live in a SCRIPTING block on the first help screen: snapshot-ID capture; content-ID capture (`c4 id -q dir/`); the description's own-ID recipe (`c4 id -q file.c4m` — its own canonical ID at its own detail level, never mislabeled a content ID); the membership probe with its one-answer nonzero; undo-handle capture AND the undo invocation (line 1 fed back as the target); journal ID extraction; the recompute pipe. Exit map, honest under multi-path: 0 ok; 1 error — lines already printed remain true claims; 2 completed with declared partiality on stderr; 3 (restore) curable, cure-then-re-run. The session journal a consumer needs is the stdout it captured plus `c4 log` — nothing to hand-roll.

## 6. The journal — semantics

`<store>/log.c4m` is an ordinary c4m patch chain: one section per claim — every `id -s` snapshot (per path), every stdin blob, every `restore --force` pre-image. Entry rule carried verbatim, one total rule per field: `- <UTC time> <size> <name>[ <- <host>:<abs-path>] <ID>` + chain boundary; mode always null; time = RFC 3339 seconds at append, provenance never identity; size = bytes of the object the ID names; name = final component of the argument's absolute path (+.c4m for descriptions; root.c4m at /; stdin/stdin.c4m for pipes, no origin), history never resolved; origin = the argument as given, symlinks unresolved, parsers splitting at the first colon (a Windows drive colon belongs to the path); the ID always the last field. Appends serialize under an advisory lock **that dies with its holder — an OS lock on the journal file, never a lockfile whose existence blocks** (a kill -9'd writer can never wedge the store; the pin closes a conforming-implementation divergence on T1's own scenario). Writers truncate a torn tail before appending; readers warn once; the entry is flushed before the print, so a torn tail belongs only to an ingest that never printed, and every complete line names a fully durable snapshot. Honesty pin: **a journal line proves its claim, never its file's completeness** — a dropped complete section is not self-detecting, which is why c4's tools are the only sanctioned writers inside a store (foreign edits are corruption; object corruption is loud because every read rehashes; the split-install swap below is the one sanctioned by-hand operation). Growth: one short line per claim; appends inspect only the tail; log streams; an absent journal is an empty history (exit 0). **Retention:** nothing expires; no c4 verb deletes; the installed journal is the complete root set a future collector consumes; nothing a journal line reaches will ever be collectable. `c4 split` shortens the LISTING only — split at N, install keep.c4m with ingest activity stopped (plain whole-file swap; indexes count from 1) — never what the store retains; the split-off archive remains part of the store's root record: keep it. Reclaiming space today means deleting a whole store directory yourself.

## 7. Exclusions — mechanism and reporting; D5's policy stays open

Mechanism, now a total rule (an unpinned dialect would let two conforming scanners mint different IDs from one command line — the condemned divergence class on T4's own input): `--exclude GLOB` (repeatable) and `--exclude-file FILE` are the ONLY mechanism. Nothing is excluded by default; no ignore file — .gitignore included — is ever read; no environment variable adds patterns (the shipped implicit C4_EXCLUDE_FILE per-directory loading is superseded: ambient env state silently changing what an ID names is invisible to scanned-alike and breaks T3). Patterns are portable globs — `*`, `?`, `[...]`, no `**`; a pattern containing `/` matches the entry's slash-separated path relative to the scan root, otherwise its bare name; matching is byte-exact, no case folding or normalization; a matched directory is pruned whole. An exclude file holds one pattern per line; blank lines ignored; no comment syntax. Identity consequence: an excluded entry is simply absent from the listing — exclusion is part of what an ID names, so "scanned alike" = same -S and same exclusion choices, and the snapshot records what was scanned, never what was omitted (out-of-band, exactly like the projection; the frozen grammar records no pattern list, and the journal entry rule is untouched — the accepted tradeoff, stated on the surface: once the tree drifts, exclusions and edits are indistinguishable in the diff report, and the applied pattern set is not recoverable from artifacts). Reporting: the ONE stderr summary line counts excluded entries and active patterns (per-pattern breakdowns would violate the decided narration pin; `c4 explain id` narrates the effective set); the recomputable report — scoped to the tree as scanned — is `c4 diff SNAP dir/` immediately after the snapshot. Safety: the pre-image is never excluded and never folded — exclusions never narrow the safety net; and the composition hazard is warned at both sites: restoring a snapshot taken with exclusions removes the excluded names from the live tree (the pre-image holds them). Exclusions never change exit status. The default pattern list is Joshua's open decision D5; this design fixes mechanism and reporting only.
