## Verdict shape

1. **The print barrier.** A snapshot ID reaches stdout only after everything the ingest stored — file bytes, listings, ID-list objects, the journal entry — is on stable media. Printed means durable; unprinted means nothing was claimed. Readable from the store side: any complete journal line found after a crash names a fully durable snapshot, verifiable in one pipe (`c4 cat -r ID | c4 id -q -`); a torn tail belongs only to an ingest that never printed. Unconditional against concurrent `gc --force` (sweep lock); interruption-agnostic.
2. **The journal.** The store names its own roots: every `-s` ingest and every `restore --force` pre-image appends one section to `<store>/log.c4m`, an ordinary c4m patch chain; `c4 log` lists it byte-stably (per journal file), oldest first; an absent journal is an empty history; nothing journaled is collectable until the journal is explicitly split. There is deliberately no ref namespace: handles are IDs; the journal is the reflog.

## 1. Identity — one mechanism, two named knowledge levels

One naming rule (frozen): the C4 ID of canonical bytes; for a directory, the one-level canonical listing of its direct children. Two named levels:
- **content ID** — listing with mode and timestamp null; names, sizes, symlink targets, and child content IDs real. Scanned alike (same -S choice), equal iff contents are byte-identical, on any machine, clock, or umask (round-5 scoping: -S is part of what is described — the design pins two IDs for the same bytes at different foldings, so the iff holds per scan choice). Default level for `c4 id`; answers T3 by string equality.
- **snapshot ID** — listing with everything observed; directory entries carry child full-listing IDs; every ID in any listing is the hash of the exact text of the object it names. Printed by `c4 id -s`; the recovery handle.

Pins: sizes derive from the scan itself — a file's recorded size is the byte count actually hashed, a directory's size is the total file bytes the scan read beneath it (recursive; null-ID entries contribute nothing), a symlink's size is its target text's byte length. Symlink entries per conflict 3 (name + target text; mode/time/ID null everywhere; null target text when readlink was refused). Hard links per round-3 repair 1: no listing form records link structure. Folded sequences per round-4 repairs 3–4 as amended round-5: fold only under -S; a folded entry records the folded name, an ID naming its stored ID-list object (member file IDs, one per line, in the folded range's order — line N names the range's Nth member; one object for both graphs), size = sum of member file sizes read and hashed, full-form mode = the members' shared mode, full-form mtime = the newest member mtime; **a run folds only when every member is a plain file, every member's bytes were read and hashed (a folded entry never records a null-ID member), and every observed member mode is equal — an unreadable member unfolds the run into ordinary entries**; the foldable-run test is fixed by the frozen c4m sequence form. A directory's mode and mtime never appear in its own listing; its parent's full-form listing records them like any entry's; the parentless scan root's own mode, mtime — and kind (round-5: argument paths resolve with OS resolution; a symlink argument names what it resolves to) — appear nowhere: provenance, not identity. Empty fixed point: an empty directory's listing is empty text, so its content ID and snapshot ID equal the empty-description constant, the same ID as zero bytes. A single file's snapshot ID and content ID coincide (its bytes). Flatten rule unchanged: a description's canonical-text ID equals its root ID at its own knowledge level. `-q` is output form, never identity selection. Hash axiom stated once: ID equality is SHA-512 equality; every store read is rehashed. Dispatch: `.c4m` and `-` parse as descriptions; all other file arguments are bytes; files inside scanned trees are always bytes; chains resolve to final state; store-address classification per conflict 4; **argument roots per round-5 repair 3: ordinary OS path resolution in every verb, final component included — dangling links are errors; symlink-ness is an entry property, never an argument-root property**. Listings scale with direct-child count; both graphs dedup across snapshots.

## 2. Self-description — the store alone recovers everything, and is addressable

`c4 id -s DIR` is a total ingest: file bytes; per-directory full-form and content-form listings (root included); the ID-list object of every folded sequence entry; one journal section per path argument. `-s` writes only inside the store. Multi-path `-s`: paths snapshot in argument order, each claimed independently; all paths attempted; exit = 1 if any failed, else 2 if any scan was partial, else 0. `id -s file` stores the file's bytes and journals them. Ingesting a description stores its listings only; `restore` pre-flights the closure. A snapshot is one walk: a tree mutated mid-scan yields a valid snapshot of what the walk read. Partial knowledge is total-ruled: an unreadable entry records name and kind from its parent's listing plus every field the scan observed, null for everything unread — size and ID always; an unreadable directory records no children; a symlink whose target text could not be read records null target text, null size, null ID; **an unreadable member of an otherwise foldable run prevents the fold — folded entries never record null-ID members (round-5 repair 2)**; a scan attempts every name its parent's listing enumerates, in canonical order; sockets, fifos, devices — and entries whose kind could not be observed at all — are reported and omitted; the same tree under the same access outcomes yields the same listing bytes from every conforming scanner.

**The store has no object types — cat is bytes.** What an ID names is knowledge the caller brings from wherever the ID came from (journal line, listing entry, ID list); cat never guesses (round-5 friction fold: stated at cat(1)). Forms that must interpret an object parse the fetched bytes as a listing and error if they do not parse; below a root, kinds come from the listing itself. No sniffing anywhere.

**ID/path edge semantics (closed).** Components split on `/`; empty, `.`, `..` are errors; matching is byte-exact against decoded recorded names (no globbing, case folding, or normalization); a folded sequence matches only its folded name — a member filename errors naming the folded entry; both `x` and `x/` present refuses bare `x` as ambiguous. Every non-final component must match a directory entry; symlink mid-path errors printing the recorded target — recorded paths never follow symlinks (argument roots do: OS resolution, round-5). Final component: directory → listing; file → bytes; folded sequence → its ID-list object, one member ID per line in the folded range's order (line N = the range's Nth member); symlink → error printing the recorded target; null-ID entry → error. Trailing slash asserts a listing. Every fetched level rehash-verified. Resolution failures are uniform: every kind exits 1 with human-level stderr; machines walk the listings (ledgered accepted tradeoff).

**Journal entry, one total rule per field (closed).** `- <UTC time> <size> <name>[ <- <host>:<abs-path>] <ID>` + chain boundary; one section per ingest. mode always null. time = UTC at append, RFC 3339 seconds (provenance, never identity). size = byte size of the object the entry's ID names. name = final component of the argument's absolute path, `.c4m` appended iff the ingest produced a description and the name lacks the suffix; root journals `root.c4m`; stdin journals `stdin` / `stdin.c4m`. Names are history, never resolved. origin = `<host>:<absolute path>` of the argument as given — symlinks are not resolved in the recorded origin, which is exactly consistent with OS-resolved argument semantics: the origin records what you typed, the operation acts on what it named. Stdin ingests record no origin link. ID = the journaled object's ID, always the last field.

**Journal growth**: one short line per ingest, not data; appends inspect only the file tail; `log` streams; `gc` reads it once per run; an absent journal is an empty history. Shortening is the explicit split recipe.
