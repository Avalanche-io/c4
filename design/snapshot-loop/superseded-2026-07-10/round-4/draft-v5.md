## Verdict shape

1. **The print barrier.** A snapshot ID reaches stdout only after everything the ingest stored — file bytes, listings, ID-list objects, the journal entry — is on stable media. Printed means durable; unprinted means nothing was claimed. Readable from the store side: any complete journal line found after a crash names a fully durable snapshot, verifiable in one pipe (`c4 cat -r ID | c4 id -q -`); a torn tail belongs only to an ingest that never printed. Unconditional against concurrent `gc --force` (sweep lock); interruption-agnostic (ordering-derived: killed process, kernel panic, power loss are one case).
2. **The journal.** The store names its own roots: every `-s` ingest and every `restore --force` pre-image appends one section to `<store>/log.c4m`, an ordinary c4m patch chain; `c4 log` lists it byte-stably (per journal file), oldest first; an absent journal is an empty history; nothing journaled is collectable until the journal is explicitly split. There is deliberately no ref namespace: handles are IDs; the journal is the reflog.

## 1. Identity — one mechanism, two named knowledge levels

One naming rule (frozen): the C4 ID of canonical bytes; for a directory, the one-level canonical listing of its direct children. Two named levels:
- **content ID** — listing with mode and timestamp null; names, sizes, symlink targets, and child content IDs real. Equal iff contents are byte-identical, on any machine, clock, or umask. Default level for `c4 id`; answers T3 by string equality.
- **snapshot ID** — listing with everything observed; directory entries carry child full-listing IDs; every ID in any listing is the hash of the exact text of the object it names. Printed by `c4 id -s`; the recovery handle.

Pins: sizes derive from the scan itself — a file's recorded size is the byte count actually hashed, a directory's size is the total file bytes the scan read beneath it (recursive; null-ID entries contribute nothing), a symlink's size is its target text's byte length. Symlink entries per conflict 3 (name + target text; mode/time/ID null everywhere; null target text when readlink was refused — repair 5). Hard links per round-3 repair 1: no listing form records link structure. Folded sequences per round-4 repairs 3–4: fold only under -S; a folded entry records the folded name, an ID naming its stored ID-list object (member file IDs, one per line, member order; one object for both graphs), size = sum of member file sizes read and hashed, full-form mode = the members' shared mode (uniformity is a fold precondition; members must be plain files), full-form mtime = the newest member mtime; the foldable-run test is fixed by the frozen c4m sequence form. The root's own mode and mtime appear in no listing: provenance, not identity. Empty fixed point: an empty directory's listing is empty text, so its content ID and snapshot ID equal the empty-description constant, the same ID as zero bytes. A single file's snapshot ID and content ID coincide (its bytes). Flatten rule unchanged: a description's canonical-text ID equals its root ID at its own knowledge level. `-q` is output form, never identity selection. Hash axiom stated once: ID equality is SHA-512 equality; every store read is rehashed. Dispatch: `.c4m` and `-` parse as descriptions; all other file arguments are bytes; files inside scanned trees are always bytes; chains resolve to final state; store-address classification per conflict 4. Listings scale with direct-child count; both graphs dedup across snapshots.

## 2. Self-description — the store alone recovers everything, and is addressable

`c4 id -s DIR` is a total ingest: file bytes; per-directory full-form and content-form listings (root included); **the ID-list object of every folded sequence entry (round-4 repair 3)**; one journal section per path argument. `-s` writes only inside the store. Multi-path `-s`: paths snapshot in argument order, each claimed independently; all paths attempted; exit = 1 if any failed, else 2 if any scan was partial, else 0. `id -s file` stores the file's bytes and journals them. Ingesting a description stores its listings only; `restore` pre-flights the closure. A snapshot is one walk: a tree mutated mid-scan yields a valid snapshot of what the walk read. Partial knowledge is total-ruled (round-3 repair 3, extended by round-4 repair 5): an unreadable entry records name and kind from its parent's listing plus every field the scan observed, null for everything unread — size and ID always; an unreadable directory records no children; **a symlink whose target text could not be read records null target text, null size, null ID (a symlink's read is readlink)**; **a scan attempts every name its parent's listing enumerates, in canonical order**; sockets, fifos, devices — **and entries whose kind could not be observed at all** — are reported and omitted (kinds a listing does not record); the same tree under the same access outcomes yields the same listing bytes from every conforming scanner.

**The store has no object types — cat is bytes.** Forms that must interpret an object parse the fetched bytes as a listing and error if they do not parse; below a root, kinds come from the listing itself. No sniffing anywhere.

**ID/path edge semantics (closed).** Components split on `/`; empty, `.`, `..` are errors; matching is byte-exact against decoded recorded names (no globbing, case folding, or normalization); a folded sequence matches only its folded name — a member filename errors naming the folded entry; both `x` and `x/` present refuses bare `x` as ambiguous. Every non-final component must match a directory entry; symlink mid-path errors printing the recorded target — paths never follow symlinks. Final component: directory → listing; file → bytes; folded sequence → its ID-list object (members fetched by those IDs); symlink → error printing the recorded target; null-ID entry → error. Trailing slash asserts a listing. Every fetched level rehash-verified. Resolution failures are uniform: every kind exits 1 with human-level stderr; machines walk the listings (ledgered accepted tradeoff).

**Journal entry, one total rule per field (closed).** `- <UTC time> <size> <name>[ <- <host>:<abs-path>] <ID>` + chain boundary; one section per ingest. mode always null. time = UTC at append, RFC 3339 seconds (provenance, never identity). size = byte size of the object the entry's ID names. name = final component of the argument's absolute path, `.c4m` appended iff the ingest produced a description and the name lacks the suffix; root journals `root.c4m`; stdin journals `stdin` / `stdin.c4m`. Names are history, never resolved. origin = `<host>:<absolute path>`, parsers splitting at the first colon; host = first dot-delimited hostname label sanitized to [a-zA-Z0-9_-], `h`-prefixed when not letter-initial, `localhost` when empty. Stdin ingests record no origin link. ID = the journaled object's ID, always the last field.

**Journal growth**: one short line per ingest, not data; appends inspect only the file tail; `log` streams; `gc` reads it once per run; an absent journal is an empty history (fresh store: `log` lists nothing, exits 0). Shortening is the explicit split recipe.

## 3. Durability — printed means durable; journaled means durable; measured, not aspirational

Platform honesty: the contract is the ordering, enforced with the strongest primitives each platform offers; the promise is exactly as strong as those primitives; constants are measurements from one machine (~130 µs/file + two ~5 ms barriers beyond reading and hashing; 20,312 files / 4.8 GB ≈ 6.1 s). Between restore's lines the tree holds a mix of old and new whole files, both endpoints durable in the store.
