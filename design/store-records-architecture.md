# Store records architecture — adjudicated recommendation

Status: RECOMMENDED (2026-07-10), pending the decisions listed at the
end. Produced by a four-stance adversarial evaluation (journal-
authoritative, master-record-authoritative, minimalist-composition,
link-web-first; each prosecuted; judged). Resolves the open question
of design/store-index-and-links.md. Nothing here is frozen.

## Recommendation

There is no single authoritative structure — the two proposals that forced one (journal-authoritative, link-web-first) both broke on the same rock: user intent stuffed into the journal's frozen grammar, via name-field squatting or a private line dialect. Instead there is one authority PER QUESTION, four in total, all plain text, no overlap: the STORE'S OBJECTS answer every recomputable question (bytes are truth; every read rehashes); the JOURNAL (<store>/log.c4m, exactly v7, zero grammar amendments) answers "what happened" and supplies the root CANDIDATE set; a new RETENTION RECORD (a small append-only store-root file, working name <store>/retain) answers "what does the user want kept" and is the ONLY structure that can ever shrink the root set; TESTIMONY RECORDS (design/testimony-record.md, own track, unfrozen) answer "what was said about IDs." Everything else — Joshua's master c4m, the c4m catalog, the reference index, the link DB, Bloom filters — is derived, rebuildable, disposable, and carries zero authority over any destructive decision.

THE RETENTION RECORD, concretely. One verdict line per deliberate act: `<root-ID> <verdict> <actor> <RFC3339-time>` with a four-word pinned vocabulary — keep, trash, shred (user-authored), drop (tool-authored at empty time, carrying the disposal class it inherited). Verdicts attach only to journaled claim roots (snapshot IDs, adopted ID-list roots); condemning an interior object is refused with an explanation (condemn the roots that reach it). Current state is a deterministic fold: latest verdict per root wins; no verdict means LIVE. Mechanics inherit v7's journal pins — OS append lock that dies with its holder, torn tail truncated at next append — plus two new pins the prosecutions proved necessary: every retention append is flushed durable BEFORE the verb reports success (retention tails carry safety decisions in both directions — a lost un-trash rescue must be impossible to report), and every retention writer holds the SHARED side of the sweep lock exactly as ingests do (so a rescue can never race the sweeper). The retention record is NEVER split: it grows one line per deliberate human act (human-scale), and its drop lines are permanent tombstones — "this ID was deliberately dropped on DATE" stays falsifiable in one command for the store's lifetime. Under the substrate map's one-line test it is class (c), testimony about IDs — a store-local testimony instance with an operational fold — which resolves link-web-first's taxonomy point without freezing the interchange format; record this as a one-line substrate-map amendment for Joshua's sign-off. Because the fold is derived, Joshua's "master c4m with trash/ and shred/ top-level folders" exists exactly as he pictured it — as the MATERIALIZED VIEW of the fold (a `c4 log --roots`-shaped query, optionally cached), rendered by Avalanche, where drag-to-trash appends one verdict line. It is never independently writable, so journal/master divergence, crash-mid-trash (an append either reported or never happened), and concurrent-master-update conflicts are all dissolved by construction rather than handled.

THE LIFECYCLE. Trash: one appended line; nothing physical changes — the root still roots its full closure, restore works (one stderr narration line; no silent state change), fully revocable by a keep line; what changes is classification and the dry-run bill. Shred: trash plus a recorded scrub obligation that rides durably in the record until disposal completes (so a crash can never silently downgrade the promise — the master-record prosecution's gap). Empty (`c4 gc --empty-trash`, long-form only, after a dry-run-default bill): the two-act boundary — trash then empty — is what stands between any kept root and dead bytes, each act journaled, durable, and reviewable, the first revocable.

THE SWEEP runs on a POSITIVE DELETION WARRANT, never negative unreachability. Under the exclusive sweep lock: (1) parse the journal (v7 grammar) and retention record (pinned verdict grammar) — a structured parse of two store-root files, never blunt token-scanning, which is what prevents the condemned-ID lists from marking themselves as the self-defeating variants did; (2) compute the keep-closure from every retained root and the drop-closure from every root being emptied, both by reading authoritative store bytes, every read rehashed, following a PINNED total grammar (canonical entry lines, bare-ID-list lines, chain boundaries — tied to the -m c conformance ID grammar; an object that is not canonical c4m text is a leaf; binary bytes are never token-scanned, killing the base58 false-positive concern on media stores; no heuristic sniff ever sits on the deletion path); (3) warrant = drop-closure minus keep-closure; append the drop verdict lines and flush — record leads, bytes follow; (4) unlink warrant objects only, leaves first and description objects last (so a crashed sweep leaves the closure recomputable); scrub-class objects first vacate the hash name (atomic rename to a non-ID staging name, then overwrite, then unlink) so presence at a hash name ALWAYS implies good bytes and the write-skip stays sound; (5) objects in NEITHER closure are reported and never touched. Pre-journal and foreign-written content is handled by a deliberate adoption step: gc refuses to exist until the retention record is initialized, and initialization walks the store and roots every object unreachable from journaled claims in an adopted ID-list object pinned by a keep line — explicit visible roots instead of silent vulnerability. Ongoing mixed fleets (a v1.0.15 writer storing without journaling after adoption) are honestly documented out of gc's contract, gated on the coordinated suite release, the same caveat class the withdrawn design confessed for git gc. SPLIT leaves the deletion story entirely: v7's "split shortens the LISTING only, never what the store retains" stands verbatim; the split tool additionally ingests its archive into the store and pins it with a keep line so the root catalog (installed journal + retained archives) is never hostage to an external file or to caller memory; per-root drop verdicts replace split as the forgetting boundary. Three v7 amendments land as text with named defects before freeze: (a) the collector consumes the root catalog filtered by the retention fold, and the deliberate-forget boundary is the drop verdict, not split — defect: split-as-forget is prefix-only and welds byte-deletion to history-forgetting, relocating the withdrawn gc's complete-enumeration burden to the split point; (b) "nothing a journal line reaches will ever be collectable" gains its pre-built falsifiable scope — "...except inside the recomputed closure of a root you explicitly trashed and then emptied, which the record permanently shows"; (c) the parked conflict-2 lock is specified, not cited: every claim path (ingest, restore, retention append) holds the shared lock from its first store interaction through its print; the collector holds exclusive through parse + closure + record + sweep, re-proving printed-means-durable-means-rooted with the collector existing.

INDEXES AND LINKS. The sweeper never reads any index — unanimous across all four prosecutions, now permanent. Idea 1 (c4m catalog) ships as a documented recipe over `c4 log` plus closure walk, honestly labeled a walk, cached only on measured demand. Idea 2 (reference index) ships LATER as a sidecar beside the store (never inside it — v7's foreign-writer pin), fed by tailing `c4 log`, fully rebuilt by store.Walk; truncated prefixes with validate-on-hit (index as hint, file as truth); plain-text sorted postings FIRST, a bespoke binary form only after a measurement shows plain text failing plus an explicit philosophy amendment; and every index carries a completeness watermark ("current through journal line N") so silence is distinguishable from not-indexed — three-valued recall, R4. The T1 benchmark runs now because it is cheap and answers Joshua's testable question, but nothing in the major depends on it. Idea 6 (link DB) is application layer — Avalanche or a c4-links sidecar repo, SQLite permissible there only with Joshua's explicit sign-off — holding one triple table with per-edge provenance classes: observed edges (machine-scanned embedded IDs — evidence, recomputable, NEVER recorded as testimony per R2, represented under a reserved REFERENCES predicate in the derived layer only) and testified edges (authored predicate lines — the signable plain-text interchange form). Different authoritative classes, one derived query surface, joined at query time never storage time, and every answer re-verified against authoritative bytes before it is reported — observed hits by opening the referrer, testified hits by re-reading the source record — so a corrupt DB can cost a rebuild, never a fabricated claim under a real author's name. One deliberate stance the design must state: links never pin bytes — retention is the retention record's job alone; a federated web where received records pinned storage would be a denial-of-service vector. Bloom-filter federation is the same mechanism as the media recall query and arrives later, app-layer, on real multi-store demand.

## The GC story (precise semantics)

ROOTS. The root candidate set is every claim in the root catalog: the installed journal plus every split archive the retention record retains (split ingests its archive into the store and pins it with a keep line, so the catalog is never hostage to an external file). The live root set is the fold: every candidate root whose latest retention verdict is none, keep, trash, or shred. Only a drop verdict removes a root. A store with no retention record is v7 verbatim — everything journaled roots its closure, nothing expires, and gc refuses to run. v7's 'roots = every journaled ID, nothing expires' is therefore the DEFAULT state of the fold, derived rather than asserted, true until the user's first deliberate act — and Joshua's 'deletion is deliberate user action, not inference' is the only way out of it.

TRASH changes nothing physical. It is one appended verdict line: the root still roots its full closure, its bytes are untouched by any sweep, restore of it works (with one stderr narration line), and a keep line revokes it. What it changes: classification in the fold view (the trash/ folder of the derived master c4m), and the dry-run bill, which reports per trashed root the bytes uniquely reachable through it — what emptying would actually free — because an object shared with any retained root survives emptying, and the bill says so. Root condemnation is never an object death warrant; mark-from-retained always wins.

SHRED is trash plus a recorded scrub obligation. It promises: after empty, the freed bytes stop being servable from this store, and the disposal pass overwrites before unlinking wherever the platform can honestly back it — stated per-platform in v7's Windows-durability voice (on CoW filesystems, wear-leveled SSDs, and under snapshots, physical erasure is not c4's to promise; the surface says exactly what was done). The obligation rides durably in the record (shred verdict, then the drop line carries the scrub class) until disposal is verified complete, so a crash between record and sweep can never silently downgrade it; an object freed by an empty that includes ANY shred-condemned root gets the scrub disposal (the stronger promise wins — closing the shared-with-trash loophole). The scrub ordering is pinned: atomically rename the object to a non-ID staging name FIRST, then overwrite, then unlink — so no crash can leave scrubbed garbage at a hash name that the presence-gated write-skip would later adopt into a printed snapshot.

JOURNAL. Untouched in grammar and role: it records claims and pre-images exactly as v7 §6 pins, and journal lines — names and IDs, not bytes — remain true statements after any collection ('this ID was stored at time T'). The journal never authorizes deletion and deletion never edits the journal. The retention record beside it holds the verdicts; its drop lines are permanent (the retention record is never split), so a swept root's restore fails closed at the existing pre-flight closure gate, exit 1, nothing touched, and one command shows the user's own trash and drop lines explaining why — honest history of a deliberate forgetting, not a silent hole.

SWEEP. `c4 gc` is dry-run by default and prints the would-be warrant as bare ID lines on stdout (data; the bill narration on stderr). `c4 gc --empty-trash` (long-form only) runs under the exclusive sweep lock, with every claim path (ingest, restore, retention append) holding the shared lock from its first store interaction through its print: (1) STRUCTURED PARSE of the two authoritative files — journal and retention record are store-root files, not ID-named objects, structurally invisible to the sweep and never token-scanned, which is why the condemned-ID lists can never mark themselves (the defect that made two proposals' collectors collect nothing); (2) MARK from bytes: keep-closure from all retained roots and drop-closure from the roots being emptied, walking authoritative store bytes with every read rehashed, following a pinned TOTAL grammar (canonical entry lines, bare-ID-list lines, chain boundaries, ID tokens per the -m c conformance grammar; non-parsing objects are leaves; binary bytes never token-scanned; no heuristic sniff on the deletion path — two conforming sweepers must compute identical survivor sets, verified by constructed-input conformance tests before shipping); no derived index is ever consulted — a stale index under-marks, and under-marking destroys data, the withdrawn gc's exact lesson; (3) WARRANT = drop-closure minus keep-closure; the drop verdict lines are appended and flushed BEFORE the first unlink — record leads, bytes follow; (4) UNLINK warrant objects only, leaves first and descriptions last so a crashed sweep leaves the dropped closure recomputable; re-run is idempotent and converges (survivors are retained, warranted, or reported); (5) objects in NEITHER closure — pre-journal strays, foreign writes — are REPORTED and never touched; adoption (the gc initialization step, required before gc will ever run) roots them explicitly in an adopted ID-list object pinned by a keep line.

WHY THIS IS SAFE — the withdrawn-gc lesson answered structurally, three inversions deep. First inversion: roots come from the machine's own durable records (journal + retention), never a caller's memory — forgetting to name something is impossible because nothing needs naming. Second inversion: absence never kills — no verdict means rooted; unaccounted-by-the-catalog means reported-and-adoptable, never swept (this closes the pre-journal-store and mixed-fleet hole that negative 'unmarked = garbage' sweeps reintroduce; ongoing pre-journal writers after adoption are documented out of contract, gated on the coordinated suite release — the one honest git-gc-class caveat). Third inversion: deletion requires POSITIVE membership in the recomputed closure of a root the user explicitly condemned twice — trash (revocable, reviewable against a printed bill), then empty (long-form, journaled, durable before effect) — minus everything any retained root still reaches. Every failure mode degrades toward retention plus a report: a torn retention tail belongs to a verdict that never reported; a crashed sweep re-runs to the same fixed point; a corrupt derived index costs a rebuild, never a wrong unlink, because none sits on the destructive path; a lost retention record entirely degrades to v7 — everything rooted, gc refuses. The one residual risk stated honestly rather than overclaimed: a keep-closure marking bug could under-protect an object shared between a dropped and a retained root — which is why the closure grammar is a pinned total rule with cross-implementation conformance tests and why the dry-run warrant is reviewable data, not why the design pretends the risk is zero.

## Rejected alternatives (do not re-litigate without new context)

- **One authoritative structure with the master record as journaled content under a reserved name (journal-authoritative)** — Name-field squatting: v7's total name rule means any user file literally named master.c4m mints a journal line byte-indistinguishable from a curation update, silently adopting arbitrary bytes as the trash list guiding a destructive sweep — the exact abuse testimony-record shape B was rejected for. Also: currency-by-newest-line inherits the journal's dropped-line hole, so curation could silently revert to a stale master in which an un-trashed root sits condemned.
- **Retention verdict lines inside log.c4m (link-web-first)** — Demotes the journal from 'an ordinary c4m patch chain' — the property every consumer (split, log, chain resolution) is built on — to a private dialect, spending v7's ledgered 0-grammar-changes line. The two records also need different lifecycles: the journal splits for hygiene; the retention record must never split so its drop tombstones stay falsifiable forever.
- **An independently-writable master.c4m tree with keep/trash/shred/archive branches (master-record-authoritative, minimalist-composition)** — Branch names carrying collector semantics are a schema smuggled through the c4m name field (the shape-B sin); the entry rule strains under ID-only pins and name collisions; it is a second mutable coordinated mechanism falsely billed to the bindings budget; and two writable authorities create the journal/master divergence and lost-update class that the derived fold dissolves by construction.
- **Triage mark + sweep-time completeness theorem (master-record-authoritative)** — The theorem forbids the design's own empty step — an emptied root is an orphan by its literal test, deadlocking the only collection event — and repairing that needs a tombstone state anyway (which the drop verdict IS). The mark also forces prefix-linear triage of tens of thousands of agent-loop sections and requires every split archive readable at sweep time (gc refuses forever after archive-to-tape). Absence-is-protection gives identical safety with zero of this machinery.
- **Roots = journal ∪ keep ∪ trash with a no-subtraction invariant; deletion only via prefix split (minimalist-composition)** — Structurally incapable of the urgent job: every object is journal-rooted, so trash frees zero bytes until a split un-roots a whole era, and condemning one mid-history snapshot forces splitting past it — un-rooting ALL earlier history and demanding a complete keep-enumeration at the split point. That is the withdrawn gc's complete-catalog burden relocated, not eliminated, and v7's undo-to-any-depth dies for the whole split era.
- **Negative-unreachability sweep: unmarked implies garbage** — Silently destroys every pre-journal store and every mixed-fleet write (a v1.0.15 writer stores without journaling; its printed ID dangles after the next gc) — the withdrawn catastrophe class widened from a race window to a version-skew hole. Replaced by the positive deletion warrant: delete only inside an explicitly-dropped root's recomputed closure minus every retained closure; unaccounted objects are reported and adoptable, never swept.
- **Blunt token-marking applied to the retention/master record itself** — Self-defeating: the record that licenses deletion names the condemned IDs, so the marker roots them and collection collects nothing (proven against two proposals). Root computation is a structured parse of the two authoritative store-root files; blunt closure marking applies only to store objects. Honest cost: the verdict grammar is pinned, counted grammar — not 'convention'.
- **Heuristic sniff on the deletion path (the withdrawn marker's sniff carried as-is)** — Sniff false negatives are under-marking — a true description whose children never mark, then sweep out from under a kept root — and an unpinned dialect lets two conforming sweepers compute different survivor sets, the condemned divergence class upgraded from wrong-ID to wrong-unlink. Replaced by a pinned total parse of the store-created description shapes tied to the -m c conformance grammar; non-parsing objects are leaves; binary bytes never token-scanned (also disposing of the base58 false-positive pinning risk on media stores).
- **Index-accelerated destructive marking with a coverage invariant (link-web-first)** — The coverage check verifies the wrong set (journal claims name roots only — interior listings are never coverage-checked) and subject-presence does not imply edge-completeness: a scanner bug's missing edge is invisible to validate-on-hit and costs a deleted live object, not a missed search hit. v7's ledger already rejected skips that are asserted rather than verified. Permanently: no derived index on any destructive path.
- **Ingest-time ID scanning inside core Put, shipped in the next major** — Nothing in the major consumes it (the sweeper marks forward from roots, never backward), and it puts an unmeasured cost on the hot ingest path v7 fought to keep honest. T1 still runs as a cheap measurement; the scanner returns later as a sidecar tailing c4 log, or core-side only behind T1 plus a real query pull.
- **A bespoke binary cache file in core, pre-measurement (the 'git-index precedent')** — The philosophy line is flat — 'no binary sidecars' — and no such license exists in any pin; derived+rebuildable answers the data-loss question, not the format question. A sorted plain-text posting file is equally derived and rebuildable and additionally greppable/diffable/comm-able. A binary form requires a failing measurement plus an explicit argued amendment plus Joshua.
- **Merging observed references and authored testimony into one authoritative structure** — Launders evidence into testimony (R2: the record never stores a claim bytes could prove): observation rows would inherit false authority, testimony rows false disposability. They unify only in the DERIVED triple index, per-edge provenance-labeled, joined at query time, each class re-verified by its own truth procedure before any answer is reported.
- **Bundling the testimony-record format freeze into the GC major (link-web-first)** — The shape is explicitly open (Joshua's decision), predicate-as-C4-ID trades away greppability and the one-line vendor cost unexamined, and it puts the one urgent deliverable behind an interchange freeze with zero current pull. The retention record borrows the predicate-line SHAPE store-locally without freezing the interchange grammar; convergence is an intent, not a dependency.
- **Shred as unlink-only, or scrub-in-place at the hash name** — Unlink-only under the name 'shred' asserts erasure the verb does not attempt; scrub-in-place is crash-unsafe — an interruption leaves scrubbed garbage AT a hash name, which the presence-gated write-skip adopts into a future printed snapshot (printed-means-durable broken with no lying drive). Shipped shred = vacate name (rename to non-ID staging) then overwrite then unlink, with per-platform honesty in v7's Windows voice.
- **Restore automatically re-rooting or un-trashing a trashed root (journal-authoritative's trash-safety mechanism)** — The mechanism does not exist under v7 — restore journals the PRE-IMAGE, never the restored target — so 'use re-claims' is false as designed. Unneeded anyway: trash changes nothing physical, so restore just works, narrates the trashed status on stderr, and suggests keep; if the root is later emptied, the materialized tree on disk is untouched and re-snapshotting re-ingests it.
